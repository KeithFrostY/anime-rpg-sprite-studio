# 四方向六層模板格式

可直接載入 `examples/six-layer-demo/template.json`；同目錄附有 24 張透明測試
PNG。這是 CPU 繪製的功能測試人偶，不代表 AI 生圖或正式美術品質。

## 素材規約

- 每個方向明確提供 `head`、`body`、`left_arm`、`right_arm`、`left_leg`、
  `right_leg`，各一次。left/right 指角色自身左右。
- 每張圖都是對齊的 256×256 PNG，只畫該部位，其餘透明。PNG 最大 8 MiB。
- 不接受完全不透明的圖層；RGB 圖不會自動去背。PNG 若含 palette 透明度，
  載入後會轉成 RGBA。拒絕多幀 PNG、錯誤尺寸與損毀圖片。
- 各層必須在同一畫布位置對齊，軀幹、手臂與腿交接處建議保留重疊區，
  避免旋轉後露出接縫。美術素材請在邊緣保留擺動餘量。
- 不以鏡像產生其他方向，也不自動拆圖或重新對齊素材。

## JSON

頂層包含 `template_version: 1`、`name`、`parameters`、`views`。
`views` 包含 front、left、right、back 四個物件，每個物件有 `direction`
與 `layers`。以下為其中一層的結構，完整範例見 examples/。

```json
{
  "part": "left_arm",
  "asset_path": "layers/front/left_arm.png",
  "joint": [93, 110]
}
```

`layers` 陣列由後往前繪製；每方向可使用不同順序。
`joint` 為原始圖片左上原點的整數像素座標，x、y 各為 0–255，
與匯出用的腳底 Pivot 概念不同。軀幹與頭部仍需提供此欄位，但目前只位移
不旋轉；手臂與腿繞各自關節旋轉。
`asset_path` 相對於 template.json 目錄；拒絕絕對路徑、`..`、跨目錄連結。
模板 JSON 最大 256 KiB。可用文字編輯器調整關節與順序，再重新載入。

參數範例：

```json
{"arm_swing": 12, "leg_swing": 10, "bob": 2}
```

皆為整數；手臂 0–30 度、腿部 0–25 度、身體起伏 0–6 像素。
步態為 `+1, 0, -1, 0`，左右手腳反向擺動，第 1、3 幀上半身抬升。
第 1、3 幀是重複的通過姿勢，符合固定四幀循環。FPS 不影響生成圖片，
只影響播放速度，套用後保存在 Walk clip 中。

## 生成與保存

1. 儲存專案，新增或選擇角色，開啟「分層模板／生成 Walk」。
2. 載入內建測試模板或上述 JSON，調整參數後生成候選。
3. 查看四方向、播放或點選幀，留意裁切警告。
4. 確認套用，才會取代原 Walk 與模板；再按主視窗儲存保存 JSON。

關閉、取消背景工作或生成失敗不會改動專案。
調整步態參數會清除候選，必須重新生成；FPS 調整不需重新生成圖片。
模板載入失敗會保留先前成功載入的模板，介面顯示錯誤，可重新選取。
所有素材在套用時複製進專案 assets/；另存時一併複製。
模板設定隨 schema 2 專案保存，schema 1 專案可讀取並升級。

此版本沒有圖形化關節編輯器、逆向運動學、落腳約束或接縫修補。
固定腳底 Pivot 是座標規約，不能保證腳不滑動；請人工檢查生成效果。
超出畫布的內容會裁切並提示，不會自動縮放或改變原素材。
