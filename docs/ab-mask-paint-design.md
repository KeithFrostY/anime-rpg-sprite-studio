# A／B 分件遮罩及補畫：第一版設計

狀態：待確認的設計；尚未實作。範圍是現有 Sprite Studio 內的基礎手動編輯器，不提供自動補圖或本機 AI。

## 目的和流程

在「A／B 單角色 Walk」選擇一個部件，開啟「編輯分件」：以同畫布的來源 PNG 或已匯入分件作起點，使用者建立及修改遮罩，然後在獨立補畫圖層修補，預覽結果並明確按「套用到候選」。回到 A／B 視窗後仍須按「套用 A／B 候選」及儲存專案。取消或關窗可放棄本次編輯，不改原圖、原分件及已保存專案。

若來源圖片尺寸與 rig 畫布不同，第一版不暗中縮放或改變座標：顯示尺寸差異，要求先選擇與 rig 同尺寸的參考圖。原本已分件且畫布符合的 PNG 可直接編輯。

## 第一版操作

- 畫布以棋盤格顯示透明；等比縮放、平移，游標轉成原圖像素座標；顯示可切換的原圖、其他部件參考與遮罩疊色，參考內容不會進入輸出。
- 多邊形套索：逐點定義閉合範圍並加入或減去遮罩；筆刷與橡皮擦可增減遮罩，調整大小及硬邊。遮罩表示可見區域，不把透明像素誤認成已補畫內容。
- 獨立透明補畫圖層：畫筆、橡皮擦、吸色器與複製筆刷；複製筆刷先在可見的來源／目前部件中指定取樣點，然後繪製。補畫可延伸至遮罩外，合成規則固定為「來源 × 遮罩，再疊補畫層」；使用者可清楚看到最終結果。吸色器只讀取畫布可見像素，透明處不虛構顏色。
- 筆刷顏色、透明度、大小；撤銷／重做預設最近 20 次操作，記憶體受限時減少可撤銷數並提示；縮放、參考圖顯示切換不改素材。
- 「預覽分件」顯示遮罩與補畫合成；「套用到候選」更新選定 A/B 分件並將其標為待補畫，是否已修好由使用者自行確認。原有 A/B 關節、圖層次序與其他部件不應改動。
- 第一版使用直線插值連接畫筆事件避免快速拖動留空；不支援壓感、圖像自動辨識、生成式補畫、任意圖層繪圖、漸層及文字工具。

## 保存與相容性

- 原圖、原始部件、可編輯單通道遮罩、RGBA 補畫層、合成後全畫布 RGBA 分件分別儲存；採專案內相對路徑與獨立檔案 ID，嚴格沿用現有路徑及符號連結越界檢查。遮罩與補畫圖層共用 rig 的畫布和左上原點。補畫圖不是生成式結果，也不聲稱能還原被遮住的真實像素。
- 建議 schema 4：A/B layer 增加可選 `edit`，包含版本、來源素材、mask、paint 等引用；舊 schema 1–3 載入升級時為空，不改原有動畫／角色／資產。舊版本讀新格式會拒絕；原路徑升級保存前建立不覆蓋既有檔案的備份。須更新 `asset_references()`、缺失檢查及另存／搬移邏輯。
- 若任何素材缺失、尺寸不一致、資料無效或空間不足，拒絕套用並保留先前候選。新素材先暫存與驗證，再由現有交易式 A/B 套用流程提交；失敗或取消移除自己的暫存檔，不刪其他內容。未儲存修改關閉前須明確提示。
- PNG 為圖片資料，JSON 只記錄各素材引用和設定；不把圖轉成 JSON。renderer 和匯出仍使用合成後的 RGBA PNG，不依賴 GUI、HTTP 或 keyring。

## 驗收與風險

1. 用不同顏色的測試圖驗證多邊形選取、遮罩筆刷加減、透明度及畫筆／複製筆刷合成的像素；複製取樣位置、邊界及透明像素需明確可測。
2. 驗證撤銷／重做、取消、未保存提示、錯誤回滾及記憶體上限；原始檔案 hash 在所有路徑保持不變。
3. 保存並重新開啟，遮罩及補畫仍可編輯；另存到新資料夾後移開原資料夾仍可預覽與再編輯。schema 1–3、既有四方向及 A/B 專案做回歸測試。
4. 用一組人工準備的不同顏色 A/B 素材完成編輯 → 套用 → 行走預覽；確認其他層及骨架不變。檢查透明、畫布尺寸、固定原點和匯出。取消、缺檔及惡意相對路徑不應損壞專案。
5. pytest／pytest-qt 驗證資料和互動；真正 Windows 桌面另檢查縮放、DPI、精細筆刷、快速拖曳及大圖反應。自動測試不等於美術驗收。

主要風險：角色原圖被遮擋處沒有真實細節；手工補畫需美術判斷。大畫布的撤銷、筆刷及圖層會耗記憶體，必須限制並實測。固定前後圖層順序與剛性變形仍可能造成穿插和接縫。
